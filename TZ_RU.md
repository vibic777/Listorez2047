## 1. Цель продукта

Настольное приложение, которое:

1. Принимает многостраничный PDF (цифровой, скан или смешанный).
2. Показывает каждую страницу в предпросмотре.
3. По профилю формы (поля + шаблоны распознавания) извлекает значения с страницы.
4. Собирает имя файла из шаблона вида `Акт о прием №{1} от {2}`.
5. Сохраняет **каждую страницу как отдельный одностраничный PDF** в выбранную папку.

OCR нужен **только чтобы подставить куски в имя файла**. Страница в выходной PDF копируется как есть (не перерисовывается в картинку).

Шаблон имени (`Акт о прием №{1} от {2}` или `имя_{505:+1}`) — это **рецепт вставки** в имя файла: поля OCR **и/или** счётчик страниц. Не содержание документа.

### 1.1. Два источника значений и три способа работы

**Откуда берётся текст для полей**

| Источник | Что это | Как достаём значение |
|----------|---------|----------------------|
| Цифра | PDF из Word / 1С / принтера, внутри уже буквы | Просто: вырезать текст по прямоугольнику поля из текстового слоя. OCR не нужен. |
| Скан | Только картинка, букв в файле нет | Сложнее: растр + RapidOCR по вырезке поля, потом паттерн. |

Галка OCR: выкл = только цифра; вкл = OCR (скан). Скан без OCR имя сам не соберёт — либо автомат с OCR, либо ручной ввод.

**Как пользователь работает (все три обязательны в MVP)**

1. **Автомат** — одна кнопка, когда лень. Сама распознаёт все страницы, собирает имена по шаблону, сохраняет. Без попапов выбора кандидата во время пакетного OCR: берёт лучший кандидат или пусто. **Пустые и неоднозначные поля** пакет не сохраняет молча — открывается окно проверки (все поля, шаблон, имя). Дубли — автосуффикс `-1`, `-2`. В конце отчёт: сколько сохранено, какие с суффиксом, ошибки. Потом можно открыть проблемную страницу и поправить руками.
2. **Постранично** — «Распознать страницу» заполняет поля, смотришь превью имени, «Сохранить» или «Следующий».
3. **Руками всегда** — любое значение поля и даже итоговое имя можно вписать/поменять, глядя на превью. Случаи: OCR полностью failed, результат не нравится, «вдруг надо поменять», цифровой текст кривой, автомат оставил дырку. Распознавание **не обязано** быть успешным, чтобы сохранить страницу.

Ручной ввод важнее OCR: что человек вписал в поле — то и идёт в шаблон, пока он сам снова не нажмёт «Распознать».

### 1.2. Объём MVP vs позже

**Входит в MVP (должно работать end-to-end):**

- Загрузка PDF, список страниц, превью: зум / отдалить / вписать в окно, скролл по X/Y.
- Галка OCR у выбора файла; папка результата; шаблон имени `{1}` `{2}` и счётчики `{505:+1#}` / `{1:+1}`.
- Рисование нескольких полей (координаты 0..1). Список слева: номер, подпись, паттерн, языки OCR поля, **Обрезать/Распознавать**, **ручное значение**.
- Кнопки: Распознать страницу, Сохранить, Следующий/пропуск, **Автомат**.
- Меню **Справка**: как работать (F1), шпаргалка (F2), «О программе». Оверлей шпаргалки на главном окне.
- RapidOCR PP-OCRv5 (CPU only), DPI 300, конфигурация с дефолтами и tooltip через i18n.
- Цифра vs скан: автоподсказка + галка OCR. Пустой паттерн — диалог (§8.6). Налезание рамок — переключатель (§7.12).
- Автовыравнивание + диалог поворота. Формат страницы A3–A6 / Letter / Legal / как в PDF / вручную мм.
- Нормализация по паттерну; попап при нескольких кандидатах (не в Автомате); ручной ввод всегда, в том числе итогового имени.
- Дубль имени: **без перезаписи** — сменить имя / Авто `-1,-2` / **Отмена**.
- Профиль: **один JSON** — поля, шаблон, формат страницы, OCR, скин/язык/иконка. Загрузить / сохранить.
- Сборка: Windows exe + Linux bin (`scripts/build_windows.ps1`, `scripts/build_linux.sh`), onefile и onedir, скрипт очистки.
- i18n `ru` / `en`. Скины и иконки из каталога. Системные кнопки окна. README ru+en.

**Не входит в MVP:**

- Полировка вёрстки, splash, «красивые» диалоги, пятый скин, безрамочное окно.
- Тонкая эвристика смешанных файлов сверх §3 / §12.
- Undo, миниатюры страниц, «применить кандидата ко всем страницам».
- Поиск паттерна вне рамки, обязательные поля, ввод пароля PDF.
- Смена DSL паттернов — модуль `pattern_dsl.py` можно заменить позже без переписывания GUI.

## 3. Уточнение вопроса 4 (цифровой PDF vs скан)

Вопрос звучал технически. Смысл такой.

**Цифровой PDF.** Файл собрали из Word / 1С / принтера. Внутри страницы уже лежат буквы с координатами. Их можно прочитать **без картинки и без OCR** — быстрее и обычно точнее.

**Скан / фото.** Внутри только изображение. Букв в файле нет. Тогда без OCR имя не собрать.

**Смешанный файл.** Часть страниц с текстом, часть — картинки.

Правила программы:

1. После загрузки PDF для каждой страницы определяется: есть ли текстовый слой (не пустой, не мусор из 1–2 пробелов).
2. Итог по файлу показывается пользователю: «цифровой / скан / смешанный».
3. Галка **OCR** рядом с путём к файлу:
   - пользователь может включить/выключить вручную;
   - при загрузке программа **предлагает** значение: нет текстового слоя → OCR вкл; текстовый слой на всех страницах → OCR выкл; смешанный → OCR вкл, но цифровые страницы сначала пробуют текстовый слой.
4. Если OCR выключен, а на текущей странице текстового слоя нет — попап: «На этой странице нет текста. Включить OCR для страницы / для всего файла / отмена».
5. Если OCR включён — страница растеризуется и идёт в RapidOCR. Текстовый слой можно использовать как запасной кандидат в попапе выбора (не вместо OCR).
6. Выходной файл **всегда** — копия исходной PDF-страницы, независимо от OCR. Растр нужен только движку распознавания.

## 4. Границы продукта (не делаем)

- Не склеиваем несколько страниц в один выходной документ.
- Не распознаём «весь документ в Word». OCR только в заданных полях и только для имени.
- Не используем GPU/CUDA (CPU only).
- Основной и единственный OCR — **RapidOCR / PP-OCRv5**.
- Не встраиваем PaddlePaddle-GPU и Tesseract.
- Не обещаем «ноль уязвимостей навсегда». Обещаем: пины версий, аудит зависимостей, без известных критических CVE на момент релиза (см. §13.1).
- Не правим содержимое PDF (кроме копирования страницы в новый файл).
- Не обещаем идеальный рукописный курсив. Цель — печатный текст и «рукописный печатный». Курсив — best-effort.
- Не качаем модели из интернета в runtime (офлайн-exe, модели внутри сборки или в папке рядом).

## 6. Ограничения железа и стратегия OCR

Лимит процесса: **≤ 4 ГБ RAM**, **2–4 ядра**.

Обязательные правила реализации:

1. Одновременно в памяти **одна** полноразмерная страница (растр OCR) + уменьшенный превью текущей страницы.
2. Страницы обрабатываются **строго последовательно**. Запрещён пул воркеров по страницам.
3. ONNX: `intra_op_num_threads = 2` (в конфиге можно 1–4), `inter_op_num_threads = 1`, `execution_mode = sequential`.
4. Модели rec не держать все три в RAM сразу. По умолчанию загружен **eslav**. `latin` и `chinese` — по флажкам в конфигурации, подгружаются лениво, при смене языка предыдущий rec можно выгрузить.
5. Растр OCR: DPI из настроек (300). Если большая сторона страницы в пикселях > `ocr_max_side` (дефолт 3508, A4@300) — пропорционально уменьшить.
6. Превью на экране — отдельный низкий DPI (96–120), не путать с OCR DPI.
7. После «Распознать все» промежуточные растры освобождать (`del` + `gc.collect()` каждые N страниц).
8. Thumbnails в списке страниц — необязательны; если есть, только крошечные JPEG в памяти, лениво, не все страницы сразу в полном разрешении.

## 7. Интерфейс

Схема ниже — **рабочий каркас MVP**, не финальный дизайн. Скины/иконки из каталога обязательны; полировать пиксели не надо. Модель данных после MVP не ломать (поля 0..1, профиль JSON, шаблон имени).

Окно — обычное окно ОС: заголовок, иконка, **стандартные кнопки свернуть / развернуть / закрыть**. Запрещено: `FramelessWindowHint`, свои кнопки окна, скрытие системного chrome. На Windows — рамка Win11/10, на Linux — рамка оконного менеджера.

### 7.1. Схема окна

```
+-----------------------------------------------------------------------+
| Файл   Профиль   Правка   Вид   OCR   Справка                         |
| Файл: [____________________] [Обзор…]  [x] OCR     [Конфигурация]     |
| Папка результата: [____________________] [Обзор…]                      |
| Шаблон имени: [Акт о прием №{1} от {2}____] [?]  [предпросмотр имени — editable] |
| Профиль: [Загрузить…] [Сохранить…]  формат [A4 ▾] [автовыравнивание x] |
+----------+---------------------------+--------------------------------+
| Страницы | Поля  [Шпаргалка]         | Предпросмотр                   |
| 1 •      | #1 Дата                   | [+] [-] [Вписать]              |
| 2 ●      | паттерн [DD.DD.DDDD    ]  |                                |
| 3 ○      | налезание [Распознавать▾] |   (изображение страницы        |
| 4 !      | значение [01.01.2024   ]  |    + прямоугольники полей)     |
|          | #2 Номер                  |                                |
|          | паттерн [{0-9}         ]  |   [=] гориз. скролл            |
|          | налезание [Обрезать    ▾] |   [||] верт. скролл            |
|          | значение [154          ]  |                                |
|          | [+ поле] [удалить]        |                                |
+----------+---------------------------+--------------------------------+
| [Распознать страницу] [Сохранить] [Следующий / Пропуск] [Автомат]     |
| статус / прогресс                                                     |
+-----------------------------------------------------------------------+
```

Статусы страницы в списке: не обработана / распознана / сохранена / пропущена / ошибка или дубль. Если страница PDF заметно другого формата, чем эталон профиля — пометка-предупреждение, рамки 0..1 всё равно те же.

### 7.2. Предпросмотр (правая панель)

- Колесо мыши / кнопки: приблизить, отдалить.
- **Вписать в окно** (fit): страница целиком в габариты панели, с сохранением пропорций.
- При зуме > fit появляются горизонтальный и вертикальный скролл (пан). Перетаскивание средней кнопкой / пробел+лкм тоже пан.
- Поля рисуются **в координатах страницы** (нормализованные 0..1). Зум и пан масштабируют и поля. Поле «приклеено» к документу, не к экрану.
- Инструменты: добавить поле (тянуть прямоугольник), выделить, переместить, изменить размер за якоря, удалить (клавиша Delete / кнопка). Пересечение рамок **не запрещаем**.
- Активное поле подсвечивается. Номер поля рисуется на рамке. Если у поля режим «Обрезать» и есть пересечение — на превью штриховкой показать **отрезанный** кусок (он в OCR этой рамки не идёт).

### 7.3. Список полей (слева)

На каждое поле:

- порядковый номер `1..N` (после удаления — плотная перенумерация);
- необязательная подпись (человеческое имя: «Дата», «Номер»);
- строка паттерна;
- **языки OCR этого поля** — галки, только из включённых глобально; пусто / «как в настройках» = все глобальные;
- **налезание:** переключатель **Обрезать / Распознавать** (см. §7.12);
- значение (editable всегда) — **своё на каждую страницу**;
- **значение по умолчанию**, галки «Вычислять выражение» и «Запоминать последнее значение» (§7.4.1);
- контраст и стратегия подготовки слабого текста (доступны в редакторе поля сразу, с первого распознавания, не только при пересканировании; сохраняются в профиле);
- индикатор: ок / не совпало с паттерном / пусто / выбрано из попапа / введено вручную.

Кнопка «+ поле» создаёт поле и включает режим рисования на превью.

### 7.4. Кнопки действий

| Кнопка | Поведение |
|--------|-----------|
| Распознать страницу | Цифра или OCR только текущей страницы, заполняет значения полей, обновляет предпросмотр имени. Не сохраняет файл. Дальше человек может править руками. |
| Сохранить | Сохраняет текущую страницу под именем из шаблона (с проверкой дубля). Имя берётся из **текущих** значений полей, хоть распознанных, хоть вписанных руками. |
| Следующий / Пропуск | Переход к следующей странице **без сохранения**. |
| Автомат | «Когда лень»: все страницы подряд в **фоновом** OCR. Предпросмотр не блокируется: зум, пан, «Сохранить вид». Прогресс немодальный. Окно проверки при стопе Автомата тоже **немодальное** (поверх, но предпросмотр доступен). Пока программа открыта, окна прогресса и проверки остаются там, куда их сдвинули (после перезапуска — снова по умолчанию; в конфигурации — кнопка сброса). Без попапов выбора кандидата во время OCR (лучший или пусто). Пустое/неоднозначное поле — окно проверки, пакет ждёт. Дубли — сразу `-1`, `-2`. Можно отменить. В конце отчёт. |

### 7.4.1. Значение по умолчанию и окно проверки

У поля рядом с паттерном:

- постоянное **значение по умолчанию** (обе галки сняты);
- **Вычислять выражение** — формулы как в шаблоне имени, в поле **значение по умолчанию**, не в паттерн OCR (`{235:+1}` → 235, 236 по номеру листа; `{505:+1#}`, `{1:+1}`, `{20:-1}`, `{2:*2}`, `{0:%10}`; `%0` даёт пустую строку без сбоя). OCR этой рамки не запускается; Автомат берёт вычисленное значение;
- **Запоминать последнее значение** — в default пишется только **применённое** значение: кнопка «Применить» в проверке или «Сохранить». Сырой OCR сам по себе не запоминается. Две галки взаимоисключающие.

Пустой OCR подставляет статичный default в форму проверки, но **не** снимает обязательную остановку Автомата. Поле с галкой «Вычислять выражение» заполняется формулой без OCR и **не** останавливает Автомат, если значение получилось непустым.

Неверный паттерн, формула в паттерне OCR вместо значения по умолчанию или сбой OCR **не роняют** программу: предупреждение, пустой результат, можно править дальше.

Окно проверки (Автомат на пустом поле, F6, сохранение с пустым полем, проверка после ручного распознавания):

- у каждого поля редактируемый выпадающий список: **результат сканирования** и **значение по умолчанию** (если оно другое); своё можно вписать;
- контраст и стратегия подготовки этого поля (те же, что в редакторе поля; стратегия доступна сразу, без галки «Усилить слабый текст»);
- **Пересканировать поле** — OCR только этой рамки, затем попап выбора: новый скан, default, ручная коррекция или отмена (отмена не затирает уже вписанное);
- Enter применяет и продолжает, Esc отменяет, Alt+S пропускает страницу, Alt+1…Alt+9 — перескан поля.

### 7.5. Диалог поворота

Открывается:

- по кнопке «Поворот…»;
- если автовыравнивание не справляется (по желанию: если оценённый угол > порога и уверенность низкая — предложить диалог).

### 7.8. Справка — «Как работать с программой»

Отдельное окно (не браузер), прокрутка, поиск по Ctrl+F желателен, в MVP достаточно скролла. Текст **вшит в приложение**: `help/how_to_ru.html` и `help/how_to_en.html`, подгружается по текущему `ui_language`. Содержание обязательно:

1. Зачем программа: режет PDF по страницам и **только именует файлы** по шаблону. Страницу не переписывает.
2. Цифра vs скан: цифра — буквы уже в PDF, OCR не нужен; скан — только картинка, нужен OCR или ручной ввод. Галка OCR.
3. Пошагово: открыть файл → выбрать папку → загрузить или нарисовать поля → шаблон имени → распознать / править / сохранить, либо **Автомат**.
4. Поля: рамка на превью привязана к странице; зум двигает и рамку; удаление перенумеровывает; в шаблоне дырки становятся пустыми. Налезание: у каждой рамки Обрезать или Распознавать.
5. Шаблон имени: `{1}` `{2}` — поля; `{505:+1#}` сохранения; `{1:+1}` лист в PDF (`+ - * %`, не `%0`). Ручная правка итогового имени.
6. Паттерны полей (тот же текст, что в шпаргалке §7.9, плюс нормализация). Пустой паттерн — диалог §8.6.
7. Три режима: Автомат / постранично / руками. Когда Автомат не спрашивает. Дубли.
8. Профили: один JSON (форма + OCR + скин), загрузить на другой файл той же формы.
9. Конфигурация: DPI 300, не больше 2–4 ядер, память, языки OCR.
10. Типичные проблемы: пустое поле, не тот фрагмент, скан кривой, защищённый PDF, налезание рамок.

Кнопка F1 / меню открывают это окно. Закрывается крестиком, программа под ним остаётся.

### 7.9. Шпаргалка паттернов — кнопка на основном окне

В основном окне две точки входа (можно одна и та же панель):

- кнопка **?** справа от поля «Шаблон имени»;
- кнопка **Шпаргалка** в заголовке колонки «Поля».

По нажатию поверх главного окна показывается **немодальная** панель (всегда сверху, можно подвинуть, не блокирует ввод в поля). Повторное нажатие / Esc / крестик — закрыть. Текст шпаргалки короткий, чтобы смотреть и сразу писать паттерн.

Содержимое шпаргалки (обязательный минимум, тот же смысл что §8):

**Шаблон имени**

- `Акт о прием №{1} от {2}` — в имя подставляется поле 1, затем поле 2.
- `{3}` если поля 3 нет — пусто, программа не падает.
- `{505:+1#}` — нумерация по **сохранениям** в сессии: 505, 506, 507…
- `{1:+1}` — номер листа в PDF.
- `{20:-1}` `{2:*2}` `{0:%10}` — минус, умножение (геометрия `N·X^i`), остаток. `%0` нельзя.
- Итоговое имя справа можно вписать руками.

**Паттерн поля (позиции: поймать → выдать в имя)**

| Пишете | Значит | Пример |
|--------|--------|--------|
| `D` | цифра | `5` |
| `H` `h` | hex верхний / нижний | `AB` / `ab` |
| `C` | буква | `А` |
| `A` | любой символ-данные | `x` |
| `{0-9}` | класс, 1+ | `154` |
| `HH.HH.HHHH` | hex; точки **мягкие** | `AB,0F FFCC` → `AB.0F.FFCC` |
| `[*>.]` или `[*\c=.]` | мусор/пусто → в имя `.` | |
| `[*>]` или `[*\d]` | мусор/пусто → **удалить** | `HH[*>]HH` → `AB0F` |
| `DD.DD.DDDD` | дата, нули слева | `1.1.24` → `01.01.0024` |

После OCR строка подгоняется под паттерн (пробелы, `01` вместо `1`, регистр H/h). Если не подошло — поле жёлтое, можно вписать руками.

Справка «Как работать» содержит эту таблицу целиком плюс пошаговые сценарии. Шпаргалка на главном окне — только таблица и шаблон, без простыни.

### 7.12. Налезание рамок

Пересечение прямоугольников **разрешено** (номер внутри даты, две колонки впритык). Запрещать рисование не надо.

У **каждого** поля свой переключатель (список полей слева; тот же смысл на рамке):

| Режим | Ключ в профиле | Что идёт в OCR / текстовый слой |
|--------|----------------|----------------------------------|
| **Распознавать** | `overlap_mode: "recognize"` | Весь прямоугольник поля, даже если внутри чужая рамка. |
| **Обрезать** | `overlap_mode: "clip"` | Прямоугольник **минус** объединение всех **других** рамок. Общий кусок этой рамке не принадлежит. |

Правила:

- Новое поле по умолчанию — **Распознавать**.
- «Обрезать» вычитает чужие **нарисованные** прямоугольники (без `field_padding_pct` соседей). Свой padding добавляется к оставшейся области.
- Если обрезать нечего (нет пересечений) — режимы совпадают, переключатель всё равно виден.
- Три и больше рамок: у поля в режиме «Обрезать» вычитаются **все** остальные, не только одна.
- Два поля оба «Обрезать» — пересечение никому; каждое читает только свою уникальную часть.
- Одно «Обрезать», сосед «Распознавать» — обрезанное поле теряет пересечение, сосед читает его целиком (типично: большая рамка + мелкое вложенное поле).
- После вычитания область может быть Г-образной (несколько прямоугольников). OCR: вырезка bounding box, вычтенные пиксели **замаскировать** (заливка фона), текст брать только из оставшегося. Цифровой PDF: символы, чьи боксы пересекают оставшуюся область. Геометрия: модуль `overlap.py` (`effective_rects`).
- Если после обрезки площади не осталось — значение пустое, статус «пусто», не падаем.
- Выходной PDF не режем: обрезка только для имени файла.

## 8. Язык паттернов полей (позиции + нормализация в имя)

Это **не** «голый regexp, который пользователь пишет целиком». Это маска **позиций**: что может лежать в рамке, и **что записать в имя файла**, когда OCR соврал (точка стала запятой, пробелом или пропала).

Движок внутри всё равно строит regexp — в `pattern_dsl.py`, с тестами. В профиле JSON поле называется `pattern`. После MVP синтаксис можно расширять, GUI хранит одну строку.

У каждой позиции два слоя:

1. **Поймать** — что OCR/текст слоя имеет право показать.
2. **Выдать** — что пойдёт в шаблон имени (`{1}`, `{2}`).

Данные (цифры, hex) ловим строго по типу. **Разделители** ловим мягко, в имя пишем канон.

### 8.1. Типы данных (ценные позиции)

Один токен = одна позиция, если нет квантификатора. Регистр токена важен (`H` ≠ `h`).

| Токен | Тип | Что ловим | Что пишем в имя |
|-------|-----|-----------|-----------------|
| `D` | цифра | `0-9`; OCR-путаницы `OоО`→`0`, `Il\|`→`1` | цифра; группа `DDD…` дополняется нулями слева |
| `H` | hex | любой регистр `0-9A-Fa-f` (OCR) | **всегда верхний** `AB0F` |
| `h` | hex | любой регистр | **всегда нижний** `ab0f` |
| `X` | hex | любой регистр | **как распозналось** `Ab0F` |
| `H!` `h!` | hex | только верх / только низ | тот же регистр, жёстко |
| `C` | буква | любой регистр | как есть |
| `U` | буква | любой | **верхний** |
| `L` | буква | любой | **нижний** |
| `U!` `L!` | буква | только верх / только низ | жёстко |
| `A` | любой символ (данные) | любой, кроме перевода строки | как есть |
| `S` | пунктуация-данные | один из `-+=.,` | как есть |
| `{a-zA-Z0-9.}` | класс | символы класса; длина **1+** (жадно, но чтобы хвост паттерна ещё сошёлся) | как есть |
| `\D` | литерал | буква D, не токен | `D` |

Квантификаторы после токена или класса: `+` `*` `?` `{n}` `{n,m}`. Пример: `D{4}`, `{0-9}`.

`HH.HH.HHHH` — это **шесть/восемь hex-позиций** плюс разделители, не «regexp точка».

### 8.2. Разделители: поймать мусор, выдать канон

Точка в `HH.HH.HHHH` **не обязана** быть точкой на скане. OCR часто даёт `,` `/` `-` `·` пробел, несколько точек, или **пусто**.

**Правило по умолчанию.** Символ `. , : ; / -` между токенами данных:

- **поймать:** 0 или больше символов, которые **не подходят** как следующая ценная позиция (не hex, если дальше `H`; не цифра, если дальше `D`). Обрезка длины: не больше 8 символов, чтобы не сожрать всю строку;
- **выдать:** ровно тот символ, что написан в паттерне (для `.` в имя всегда `.`).

Поэтому `HH.HH.HHHH` из `AB,0F FFCC`, `AB 0F FFCC`, `AB0FFFCC`, `AB·0F·FFCC` → **`AB.0F.FFCC`**.

Пробел в паттерне: ловим любой прогон пробелов, в имя один пробел.

Литерал вроде `№` — точное совпадение, в имя как есть.

Контекстный якорь записывается как `@{текст}`. Он требует маркер в OCR-тексте, но не добавляет его в значение поля. Пример `@{№}D{1,4}` ищет от 1 до 4 цифр после знака номера и не выдаёт сам знак; для `№` также принимаются частые варианты OCR `No`, `Nº`, `N°`. Несколько вариантов задаются через `|`, например `@{№|No|Nº}D{1,4}`. Якорь ограничивает поиск по уже распознанному тексту, но сам по себе не восстанавливает символы, которые OCR совсем не распознал.

### 8.3. Явная позиция-разделитель `[…]`

Когда дефолта мало: квадратные скобки = слот «не данные».

Формат: `[что_ловим>что_пишем]`

| Пишете | Ловим | В имя |
|--------|-------|-------|
| `.` между `H`/`D` | см. §8.2 (сахар) | `.` |
| `[*>.]` | любой мусор 0…8 или пусто | всегда `.` |
| `[*>,]` | то же | всегда `,` |
| `[*>]` или `[*\d]` | мусор или пусто | **удалить** (в имени разделителя нет) |
| `[*\c=.]` | то же, что `[*>.]` | всегда `.` (канон) |
| `[.>.]` | только символ `.` (жёстко) | `.` |
| `[./>-]` | только `.` или `/` | `-` |

Смысл пользовательских черновиков:

- `[.*\d]` — «что попало, точку из имени убрать»;
- `[.*\c=.]` — «что попало (даже пусто), в этой позиции в имени поставить `.`».

`.*` внутри скобок = синоним `*` (прогон мусора, не regexp-жадность на всю строку). `\d` = delete, `\c=X` = canonicalize в символ `X`. Предпочтительная запись в шпаргалке: `[*>.]` и `[*>]`.

Пример: шифр без точек в имени, хотя на бланке они есть — `HH[*>]HH[*>]HHHH` из `AB.0F.FFCC` → `AB0FFFCC`.

### 8.4. Поиск внутри поля

OCR/текст слоя может вернуть несколько строк и мусор вокруг.

1. Собрать текст поля (сверху вниз, слева направо).
2. Найти **все** непересекающиеся совпадения паттерна.
3. Каждое совпадение **выдать** по правилам слотов (канон), не сырой OCR.
4. 1 совпадение — подставить. 0 — пусто (в проверке подставляется значение по умолчанию, если задано), ввод руками. ≥2 — попап постранично (список сканов + default + можно вписать своё); Автомат без этого попапа берёт лучшее или пусто и при пустом/неоднозначном открывает окно проверки §7.4.1.

Паттерн ищет совпадение внутри распознанного текста; символы до и после совпадения не выдаются. Например, `DD.M` из `«27» 03 2026 г.` выдаёт `27.03`, а из `«27» марта 2026 г.` тоже `27.03`: кавычки и год остаются за пределами совпадения, словесный месяц нормализуется к номеру.

Выданная строка должна соответствовать **канону** паттерна. Если после нормализации не сходится — сырьё в поле, жёлтым, предупреждение.

### 8.5. Нормализация ценных позиций

- Края обрезать.
- Группы `D`: слева нули до длины (`1.1.2024` + `DD.DD.DDDD` → `01.01.2024`).
- `H` / `h` — регистр как в токене.
- Путаницы OCR только на однозначном типе: в `D` `O→0`, `I→1`; в hex `O→0`; в `C` цифры в буквы не конвертировать.

Примеры:

- дата: `DD.DD.DDDD`
- hex-код: `HH.HH.HHHH`
- номер: `{0-9}`
- «точки выкинуть»: `HH[*>]HH[*>]HHHH`

### 8.6. Пустой паттерн

Паттерн не задан — **не** распознаём молча и **не** стопорим без спроса.

Постранично «Распознать»: окно «Паттерн поля N пуст. Продолжить (взять весь текст рамки как есть) или задать паттерн?»

- **Продолжить** — сырой текст из рамки, края обрезать, без канона hex/точек;
- **Задать паттерн** — это поле не заполнять, фокус в строку паттерна;
- **Отмена** — прервать распознавание страницы (уже заполненные поля этой страницы не откатываем).

Автомат: если среди полей есть пустые паттерны — **одно** окно на пачку: продолжить для всех пустых / отменить Автомат. В отчёте перечислить такие поля.

## 9. Профили — всё в одном файле

Один JSON-профиль — переносимый снимок **и формы, и настроек**. Загрузить = получить те же поля на странице, тот же шаблон имени, тот же OCR и тот же скин.

Содержимое:

- имя профиля, версия формата (`1`);
- шаблон имени (`{1}`, `{505:+1#}`, …);
- поля распознавания: номер, подпись, паттерн, прямоугольник `{x, y, w, h}` в долях 0..1, **`ocr_langs`** (`[]` = как глобально), **`overlap_mode`** (`"recognize"` \| `"clip"`, по умолчанию `"recognize"`), **`default_value`**, **`default_is_expression`**, **`remember_last_value`**, **`contrast`**, **`preprocess_strategy`**;
- эталон страницы для рамок:
  - выбор из списка: **A3, A4, A5, A6, Letter, Legal**, плюс **«как в PDF»** (взять mediabox текущей страницы) и **«вручную»** (ширина × высота в мм, книжная/альбомная);
  - в файл профиля пишем `page_format` (`A4` / `custom` / `from_pdf`) и при custom — `page_width_mm`, `page_height_mm`, `page_orientation`;
  - при загрузке сравниваем с реальной страницей PDF; если пропорции или формат сильно другие — предупреждение «рамки с другого формата», не блокируем, пользователь двигает поля. Страницы внутри файла разного размера — та же раскладка 0..1, у «чужих» листов статус-предупреждение.
- автовыравнивание (по умолчанию включено), рекомендация галки OCR;
- параметры движка из конфигурации: DPI, потоки, языки OCR, порог, det/rec и остальные ключи §11;
- оформление: `ui_language`, `ui_skin`, `ui_icon`, `ui_icon_locked`;
- папка результата `output_folder` и галка `output_relative` (относительный путь от папки PDF/профиля).

Не кладём в профиль (это сессия, не форма):

- значения OCR / ручной ввод полей;
- путь к открытому PDF;
- `save_index` / номера `{…#}` — при открытии файла всё равно сброс;
- список страниц и статусы сохранения.

Действия: Загрузить… / Сохранить / Сохранить как…. Меню «Профиль» и кнопки на панели. Формат файла, например `.pdfocr.json` (или `.json`).

Загрузка применяет **всё сразу**: поля рисуются на превью, шаблон, OCR, язык, скин, иконка. Если в окне уже были поля — подтверждение «заменить текущую раскладку и настройки?».

Один открытый PDF — один активный профиль (решение A). Локальный `config.json` — только последний снимок на этой машине (старт программы без файла профиля). Сохранить профиль = выгрузить текущее состояние в файл, который можно отдать коллеге.

## 10. Именование и сохранение

### 10.1. Шаблон

Два вида вставок. Разбор **сначала счётчика** (есть `:` и операция), потом полей. Иначе `{1:+1}` не должен превратиться в поле `{1}`.

**Поле:** `{n}` — значение поля с номером `n`.

- `Акт о прием №{1} от {2}`
- Нет такого поля → пустая строка + предупреждение, без исключения.

**Счётчик:** `{N:op}` или `{N:op#}`. Целые, без вещественных.

- **Без `#`:** `i` = номер страницы в открытом PDF (с нуля). `{1:+1}` → 1, 2, 3… лист файла. Пропуск страницы всё равно двигает число.
- **С `#` (основной для «просто нумерация»):** `i` = сколько файлов **уже успешно сохранено в этой сессии**. Пропуск не считается. Шаблон `имя_{505:+1#}` → 505, 506, 507 в порядке сохранений, даже если это листы 10, 2 и 40.

| Запись | Индекс | Пример |
|--------|--------|--------|
| `{505:+1#}` | сохранения | 505, 506, 507 по факту Save |
| `{1:+1}` | страница PDF | лист 1→1, лист 10→10 |
| `{10:+2#}` | сохранения | 10, 12, 14 |
| `{20:-1#}` | сохранения | 20, 19, 18 |
| `{2:*2#}` | `N · X^i` | 2, 4, 8 |
| `{0:%10#}` | `(N+i) mod X` | по сохранениям |

Правила:

- Пробелы допустимы: `{505: +1#}`.
- `%0` запрещён: пусто + предупреждение, без падения.
- Можно мешать: `Акт_{1}_{505:+1#}`.
- Предпросмотр имени **можно править руками**. Recognize / Автомат перезаписывают его из шаблона. Save берёт то, что в этом поле.
- Сессия открытого PDF:
  - `save_index` — сколько файлов **уже успешно записано** (0-based индекс для **следующей ещё не нумерованной** страницы);
  - `page_save_slot[номер_страницы]` — индекс `#`, выданный при **первом** успешном Save этой страницы. Повторный Save — тот же слот. Пропуск слот не занимает.
  - Превью несохранённой страницы считает `#` по текущему `save_index`. Превью уже сохранённой — по её слоту.
  - После успешной записи, если слота не было: записать `save_index` в слот страницы, затем `save_index` += 1.
- **Сброс `#`:** открытие другого PDF, повторное открытие того же файла, закрытие файла — `save_index = 0`, слоты пустые.

После удаления поля поля перенумеровываются `1..N`. Шаблон автоматически **не переписываем**. Предупреждение: «Поля перенумерованы. Проверьте шаблон имени.» Счётчики `{505:+1}` от удаления полей не зависят.

### 10.2. Санитизация Windows

Запрещённые символы `\ / : * ? " < > |` заменить на `_`. Убрать хвостовые пробелы и точку. Пустое имя → `page_{номер_страницы}`. Длина имени разумная (не больше 150 символов + `.pdf`).

### 10.3. Дубли имени — перезаписи нет

Тихая перезапись файла **запрещена**. Если целевое имя уже есть на диске или уже выдано в этой сессии (в том числе повторный Save той же страницы):

Попап, три действия, **Отмена обязательна**:

- текст: файл уже существует;
- **сменить имя** — поле ввода, сейчас стоит текущее имя (без `.pdf`);
- **Авто** — суффикс `-1`, `-2`, `-3`… первый свободный;
- **Отмена** — не писать файл, счётчик `#` не двигать.

Повторный Save той же страницы: номер `{…#}` у страницы уже занят → снова это окно, не overwrite. «Авто» даст `имя-1.pdf`. Новый **другой** лист берёт следующее `#`.

**Автомат** (пачка): окно на каждый дубль не показываем (иначе сотни кликов). Сразу вариант «Авто» (`-1`, `-2`). В конце отчёта перечислить, какие имена получили суффикс. Отмена пачки — отдельная кнопка прогресса, уже сохранённое не удаляем.

### 10.4. Содержимое выходного файла

Одностраничный PDF: исходная страница, с учётом поворота, заданного пользователем. Аннотации/картинки страницы сохраняются. Имя — только снаружи, в имени файла.

### 10.5. Куда писать

Папка результата выбирается сверху. Если не выбрана — перед первым сохранением запросить.

### 10.6. Отчёт Автомата

После пакетного прогона — короткое окно:

- сохранено N;
- пустые/неоднозначные поля пакет не сохраняет молча — они уже разобраны в окне проверки (§7.4.1);
- с суффиксом из-за дубля: список;
- ошибки (занят файл, память): список;
- кнопка «Закрыть». Можно кликнуть страницу в списке слева и поправить руками, затем Сохранить.

## 11. Конфигурация OCR (меню)

Хранить в `%APPDATA%/Listorez2047/config.json` (и рядом с exe как переопределение для портативного режима: `config.json` в папке exe, если есть). Старые `%APPDATA%/PDFOCRsplitter` и `%APPDATA%/Listorez` читаются, пока нового файла нет; запись идёт уже в `Listorez2047`.

Все параметры ниже обязательны в UI. Дефолт = «оптимальное качество в лимите 4 ГБ».

| Ключ | Дефолт | Смысл для tooltip |
|------|--------|-------------------|
| `dpi` | 300 | Разрешение растра для OCR. 200 быстрее и грубее, 400–600 лучше мелкий шрифт, но память и время растут. 300 — баланс. На превью не влияет. |
| `ocr_max_side` | 3508 | Макс. сторона растра в пикселях. Больше — лучше мелкий текст, выше RAM. 3508 ≈ A4 при 300 DPI. |
| `cpu_threads` | 2 | Потоки ONNX внутри одной страницы. Ставить 2, максимум 4. Больше 4 на этой машине нельзя: заберёт систему. |
| `use_angle_cls` | true | Классификатор 0°/180°. Если страница вверх ногами — перевернёт текст для распознавания. Чуть медленнее. |
| `auto_deskew` | true | Выровнять небольшой перекос скана до OCR. Не заменяет ручной поворот на 90°. |
| `drop_score` | 0.50 | Минимальная уверенность блока OCR (0–1). Ниже — блок выкидывается. 0.3 больше мусора, 0.7 может потерять бледный текст. |
| `det_limit_side_len` | 1280 | Внутренний размер детектора текста RapidOCR. 960 быстрее, 1280–1920 лучше мелкие строки. |
| `rec_batch_num` | 6 | Сколько текстовых блоков распознавать пачкой. Больше — чуть быстрее, больше RAM. 4–8 норма. |
| `lang_eslav` | true | Галки языков OCR. Русский (eslav) **по умолчанию включён**. |
| `lang_latin` | false | Латиница: EN, DE, FR, ES и др. Включать, когда на форме латиница. |
| `lang_chinese` | false | Китайский. Модель крупнее. |
| `prefer_native_text` | true | На цифровых страницах сначала пробовать текстовый слой PDF в координатах поля. |
| `field_padding_pct` | 5 | Расширить поле на N% при вырезке, чтобы не срезать края букв. |
| `ocr_contrast` | 1.0 | Глобальный контраст слабого текста. 1.0 — выключено. |
| `default_preprocess_strategy` | `standard` | Стратегия подготовки новых рамок с первого распознавания. Можно сменить у поля без пересканирования. |
| `ui_language` | `ru` или язык ОС | Язык интерфейса из словаря. |
| `ui_skin` | `it_gray` | Скин: `it_gray` / `auto_black` / `gas_blue` / `transport_green`. |
| `ui_icon` | `it` | Иконка окна: `it` / `auto` / `gas` / `transport`. |
| `ui_icon_locked` | false | true — иконку выбрали вручную, скин её больше не меняет. |

Кнопка «По умолчанию» восстанавливает таблицу выше.

### 11.1. Языки OCR: глобально и в поле

В конфигурации — **галки**, не один список. По умолчанию только **русский**. Можно включить все. Снять все нельзя: минимум одна галка.

Смысл глобальных галок: какие rec-модели **вообще можно** грузить (слои поиска).

У каждого поля распознавания — те же галки **точнее**:

- доступны только языки, включённые глобально;
- ничего не отмечено в поле = «как глобально» (все включённые сверху);
- отмечены два из трёх = на этой вырезке гоняем только их.

Пример: глобально ru+латиница+китайский; поле «Дата» — только русский (цифры и так есть); поле «Name» — только латиница.

Новое поле: языки **наследуют глобальные**, по паттерну сами не угадываем (`DD.DD.DDDD` не включает «только русский»). Кто хочет быстрее — снимает лишние галки на поле. В шпаргалке — одна строка об этом.

На вырезке поля: det один раз, rec **по очереди** по выбранным языкам поля (не держать три модели в RAM). Кандидаты с оценкой в один список → паттерн. Цифровой PDF: текстовый слой без моделей, галки языка на него не влияют.

В профиле: глобальные `lang_*` и у поля массив `ocr_langs` (`[]` = наследовать).

## 12. Определение скан / цифра

Для страницы:

1. Извлечь текст PyMuPDF.
2. Если символов (без пробелов) ≥ 30 **или** есть текстовые span внутри хотя бы одного поля профиля — считать, что текстовый слой полезен.
3. Иначе — скан/картинка.

Эвристика грубая, поэтому галка OCR — главный рубильник, автоопределение только предлагает.

- Интерфейс: русский и английский из словаря; все строки UI только через i18n-ключи, не хардкод.
- Скины и иконки из каталога, не захардкоженные цвета в виджетах.

- Понятные ошибки: файл занят, PDF битый, папка недоступна, модель не найдена, не хватило памяти — без traceback в лицо; traceback в лог.
- Лог: по умолчанию **выключен**. При включении — один файл `Listorez2047.log` рядом с exe или `%APPDATA%/Listorez2047/Listorez2047.log`. В конфигурации галки уровней TRACE / DEBUG / INFO / WARNING / ERROR / CRITICAL (по умолчанию все включены).
- Папка результата: абсолютный или относительный путь (галка); путь сохраняется в профиле. Если папки нет — предложить создать, показав полный путь.
- Новое поле распознавания: по умолчанию включено «Запоминать последнее значение»; автовыравнивание по умолчанию включено.
- Отмена длинной операции (пакетное распознавание).
- Прогресс: «страница 3 из 40».
- Старт onefile может быть медленным (распаковка во temp) — показать splash «Загрузка…».

## 15. Технические умолчания (не переоткрывать)

Заказчик это явно не называл; заложено, чтобы агент не стопорился и не спрашивал:

1. Выход всегда PDF (копия страницы), не JPG.
2. GUI PySide6, не Tkinter.
3. Только RapidOCR / PP-OCRv5. Две portable-сборки: onefile и onedir по флагу.
4. `C` = любая буква Unicode, не только латиница.
5. `{класс}` = один или больше символов.
6. Поворот в диалоге применяется к текущей странице; галка «ко всем».
7. UI через словарь; MVP языки `ru` и `en`. Стандартные кнопки окна ОС.
8. Китайская модель в комплекте, по умолчанию выключена.
9. **Автомат:** дубли без спроса, суффикс `-1`, `-2`; пустые поля — окно проверки, не тихий пропуск; в конце отчёт. Постраничное сохранение — попап дубля.
10. В выходной PDF страница поворачивается, если пользователь повернул её на экране.
11. Геометрия налезания — `src/listorez2047/overlap.py`. Шаблон имени — `naming.py`. Паттерны — `pattern_dsl.py`. Не дублировать логику в виджетах.
